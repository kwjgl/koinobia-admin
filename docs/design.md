# 설계서 (koinobia-admin)

설계의 기준은 이 파일 하나다. 옛 계획은 `plan.md`(끝남).

## 1. 무엇인가
코이데·디다코·(나중에) 텔리오의 이용 통계와 운영 도구를 한곳에 모은 운영자(앱 관리자) 전용 페이지. 앱 관리자만 들어온다. 서버는 pray-for의 Supabase다. 메뉴는 일곱 개다: 오늘, 교회 신청, 교회(스위치 포함), 이용 통계, 의견함, 공동체, 저장 공간. 기록 내용(이름·기도제목·기록 글)은 보이지 않는다(예외 셋은 아래 표).

## 2. 지킬 약속 5가지 (모든 PR 검토 때 이 표로 본다)

| 약속 | 어떻게 지키나 | 확인 방법 |
|---|---|---|
| 기록 내용이 안 보인다 | 이름·기도제목·기록 글을 부르는 서버 함수를 만들지 않는다. 예외는 운영자가 읽으라고 받은 글 셋뿐: 의견함 글, 교회 신청서(연락처·대표 목사님 이름), 공동체 신고 상세 | `js/api.js`가 부르는 함수 목록이 4장 표와 같은지, 셋 밖에 글을 싣는 함수가 없는지 |
| 이용 통계의 선 4가지를 지킨다 | 이름·내용을 모으지 않는다, 개인 단위로 안 보여 준다, 13개월만 본다, 처리방침을 먼저 한다(`usage-stats.md`). 2026-11-20부터 5명 미만 가림은 없다(서버 038). 옛 서버가 `small`을 주면 0이 아니라 '5명 미만'으로 그린다 | 데모 `?demo=small`·`?demo=empty`, 결과에 사람·교회 번호가 없는지 |
| 교회끼리·사람끼리 순위·비교가 없다 | 교회 목록은 만든 순서, "많은 순" 정렬 없음, 이용 통계는 교회 구분 없이 앱 전체 합계만 | 화면 검토 |
| 교재·편성·리더 지정이 없다 | 교재 칸·버튼, 부서·사랑방 편성, 리더 지정을 만들지 않는다. 교회 단위까지만 | 화면과 코드에 해당 낱말이 없는지 |
| 숫자와 그래프는 이 사이트에서만 | 앱 화면은 숫자로 재지 않는다(앱 원칙). 운영자 사이트의 숫자·그래프는 이용 통계 메뉴에만, 앱 전체 합계로만 | 이용 통계 밖에 그래프가 없는지 |

덧붙임: "받은 일 개수"(신청·의견·신고·저장 공간)와 교회 카드의 합계(가입 수, 부서 수 등)는 이용 행동이 아니라 운영 사실이므로 5명 미만이어도 가리지 않는다. 개인 이름은 싣지 않는다.

비밀값(`service_role`, `sb_secret`, Supabase 콘솔 비밀, 시트 주소, PIN)과 실제 이름은 저장소에 올리지 않는다. 사이트에는 `SUPABASE_URL`과 publishable 키만 둔다.

## 3. 화면 원칙
- 코이데 기본(초록) 테마, 늘 밝은 화면. 코이데 기본 테마의 밝은 값을 `css/admin.css` `:root`에 고정하고 `color-scheme: light`. 어두운 모드·기기 설정 분기 없음. 화면 색은 코이데 변수만 쓰고, 그래프는 그래프 전용 팔레트(`--chart-1~5`·`--chart-other`, 차례 `--seq-1~5`)만 쓴다.
- 글꼴·크기는 코이데와 같다(제목 Gowun Batang, 본문 IBM Plex Sans KR, 휴대폰 16px, PC 15px). 터치 영역 44px 이상.
- 이모지·장식 없음. 서버가 준 글은 글자로만 넣는다.
- 화면 흐름: 로그인 전 → (앱 관리자 아님이면 안내 + 로그아웃) → 일곱 메뉴(오늘, 교회 신청, 교회, 이용 통계, 의견함, 공동체, 저장 공간) → 푸터(로그인 방법·로그아웃, 화면 버전은 로그인 방법 옆 도움말 안). 위험한 동작(멈춤·만들기·거절·닫기·스위치 켜기)은 한 번 더 확인 단계를 둔다. 스위치는 값을 고른 뒤 확정 상자에서 확정해야 서버에 간다.
- 로그인 전: 가능한 방법마다 버튼(카카오·구글·애플, 목록은 Supabase 설정에서 읽고 실패하면 카카오), 공용 컴퓨터 안내. 로그인은 이 기기에 유지된다(`storageKey: koinobia-admin-sb`). 로그인에서 돌아온 `?code`는 주소에서 지운다.
- 앱 관리자 아님: 내 계정 번호(복사 버튼)·로그인 방법을 보여 주고 "코이데에서 쓰던 방법과 같은지 확인", "번호를 채팅·GitHub에 올리지 마세요", 로그아웃.
- 껍데기: 메뉴 줄(휴대폰에서는 줄바꿈 칩 두 줄, 각 44px 이상), 해시 주소(`#/today` 등)로 이동하고 새로고침해도 그 메뉴. 메뉴 옆 배지는 오늘 결과(신청 기다림·안 읽은 의견·새 신고). 푸터에 로그인 방법(옆 도움말 안에 화면 버전)·로그아웃. 아직 없는 메뉴는 "준비 중".
- 오늘: 신청 기다림·안 읽은 의견·새 신고·활동 관리자 없는 교회·멈춘 교회(0이면 줄을 숨김, 모두 0이면 "오늘 할 일이 없어요"), 저장 공간(70% 넘으면 주황), 교회 수, 스위치 세 개의 상태(켜짐·관리자만·꺼짐), `usage_track`이 꺼져 있으면 한 줄 안내.
- 이용 통계: 위에 앱 고르기(전체·코이데·디다코·텔리오)와 기간(7·30·90·365일), 아래에 탭 여섯(한눈에·기능·흐름·다시 오는 사람·시간·기기·앱). 탭을 열 때만 그 탭의 함수를 부르고, 같은 요청은 60초 기억한다. 그래프는 `js/charts.js`가 직접 SVG로 그린다(꺾은선·면적·세로/가로 막대·누적 막대·100% 누적 막대·도넛·반원 게이지·상자 그림·시간대 히트맵·깔때기·코호트 히트맵 표·숫자 타일). 그래프 종류는 데이터에 맞게 고른다. 각 그래프는 요약 `aria-label`과 "표로 보기" 단추를 가지고, 값을 짚어 볼 수 있는 그래프(꺾은선·세로 막대·누적 막대·시간대 지도)는 마우스를 올리거나 탭하거나 방향키로 움직이면 말풍선(기간과 값)이 뜬다. 나머지는 `role="img"`다. 눈금은 정수 단위이고 0인 막대에는 숫자를 달지 않으며, 쓰이지 않는 계열은 범례에서 뺀다. 서버가 가린 값(`small`)은 0이 아니라 점선 빈 칸과 "5명 미만"으로 그린다. 여러 계열은 범례와 숫자 라벨로도 구분한다. 한눈에 탭에 고착도(달별 꺾은선, 이번 달은 속이 빈 점과 "진행 중")와 새로 온 사람·다시 온 사람(누적 막대), 다시 오는 사람 탭에 사용 빈도 분포, 시간 탭에 머문 시간(상자 그림과 구간 히스토그램, 037)이 있다. 기기·앱 탭의 구성 비율은 도넛, 저장 공간은 반원 게이지다. 037이 서버에 없으면 그 카드에만 "서버 SQL 037이 아직 없어요"를 보인다. 흐름 탭의 미리 만든 흐름 4개는 usage-stats.md 4장 이름을 쓴다(교회 첫 접속은 건너뛰는 화면이 있어 단계 셋만).
- **도움말(툴팁)**: 풀이·안내 글은 제목·라벨 옆 '?' 단추를 눌러 보는 도움말로 둔다(`UI.info`/`UI.withInfo`). 되돌릴 수 없다는 경고, 신청자에게 보이는 글, 서버 오류와 상태 글은 눈에 보이게 둔다. 도움말·그래프 말풍선 위치는 CSS 클래스와 SVG 속성으로만 잡는다(`style` 속성·CSSOM 위치 지정 없음).
- 보안 머리글(CSP)은 `index.html` 메타로 둔다(`script-src 'self'`, `connect-src`는 Supabase 한 곳). `connect-src`의 호스트는 `config.js`의 `SUPABASE_URL`과 같게 손으로 맞춘다(바뀌면 둘 다 고친다).
- 서비스워커·홈 화면 앱은 두지 않는다. 화면 버전은 `config.js`의 `VERSION`.

## 4. 서버를 부르는 방식
- 서버 부르기는 `js/api.js` 한 파일에만 둔다. 화면 코드는 `api.today()`처럼 뜻으로만 부르고 서버 함수 이름·요청 모양을 모른다.
- 로그인은 `supabase-js`(Supabase 로그인)가 한다. 관리자 판정은 서버(`admin_me`)만 믿는다. 화면에서 메뉴를 숨기는 것은 편의일 뿐이다.
- 모든 함수는 `authenticated`만 부를 수 있고, 첫 줄에서 앱 관리자인지 본다(`admin_me`만 예외). 인자 모양은 pray-for `supabase/`의 SQL 머리 주석을 본다.

| 메뉴 | 서버 함수(pray-for) |
|---|---|
| 로그인 | `admin_me`(036) |
| 오늘 | `admin_today`(036) |
| 교회 신청 | `church_apply_admin_list`, `church_apply_make`, `church_apply_reject`(035) |
| 교회·스위치 | `admin_church_list`, `admin_church_create`, `admin_church_rename`, `admin_church_state`, `admin_church_code`, `admin_church_invite`, `admin_setting_list`, `admin_setting_set`, `admin_log_list`(036) |
| 이용 통계 | `admin_usage_active`, `_signups`, `_retention`, `_features`, `_funnel`, `_heatmap`, `_devices`, `_cross_app`, `_dormant`(006), `admin_usage_stickiness`, `_frequency`, `_duration`, `_new_returning`(037) |
| 의견함 | `admin_feedback_list`, `admin_feedback_mark_read`(006) |
| 공동체 | `admin_community_health`, `admin_community_lookup`, `admin_community_close`(005·006), `admin_community_reports`(036) |
| 저장 공간 | `admin_db_size`(006) |

- 036·037이 서버에 아직 없으면 해당 메뉴는 "서버 SQL이 아직 없어요"를 보여 준다.

## 5. 결정 기록
- **2026-11-09 관리 페이지를 새 저장소에 따로 둔다.** 이유: 코이데 화면 파일이 커서 관리 화면을 고칠 때마다 코이데 전체·캐시 번호·배포를 건드려야 하고, 다른 주소에 두면 앱 관리자 로그인이 일반 앱 화면과 섞이지 않는다.
- **2026-11-09 서버는 지금 기본 서버를 그대로 쓴다(새 서버 없음).** 이유: 비밀 열쇠가 있는 곳을 늘리지 않고, 사용자가 할 서버 일을 줄인다. (2026-11-19에 바뀜: 아래 줄)
- **2026-11-09 화면은 늘 검은 색으로 고정한다.** 이유: 사용자가 정했다. 코이데 먹색 어두운 값을 쓰고 밝은 모드는 두지 않는다.
- **2026-11-09 저장소는 공개, 주소는 `admin.koinobia.com`(GitHub Pages).** 이유: 비밀값이 없고 koide도 공개다. 다른 하위 주소라야 대문(`koinobia.com`)과 브라우저 저장소를 나눠 쓰지 않는다.
- **2026-11-09 서버 부르기는 `js/api.js` 한 곳에만 둔다(Supabase 대비).** 이유: 나중에 Supabase로 바꿀 때 화면 코드를 고치지 않고 `api.js` 안쪽만 바꾸려고. (2026-11-19에 바뀜: 아래 줄)
- **2026-11-09 관리자가 명단에서 사람을 뺄 때 디다코 기록은 지우지 않는다.** 지우기는 본인이 나갈 때만 한다. 이유: 실수로 지우면 되돌릴 수 없다.
- **2026-11-09 디다코 교회 관리자를 누가 세울지는 3단계에서 정한다.** 당분간 앱 운영자가 겸한다.
- **2026-11-09 "이 교회로 들어가기"는 일회용 통행증(enterPass/enterOpen) 방식으로 한다.** 이번 뼈대 PR에서는 만들지 않는다(1-5).
- **2026-11-09 일 나누기를 바꿨다: 계획과 검토는 Claude, 작업(파일 고치기·커밋·push·PR)은 Codex.** 이유: 사용자가 정함(사용량을 나누고, 쓰는 사람과 보는 사람을 나눠 서로 확인하려고). (2026-11-19에 바뀜: 아래 줄)
- **2026-11-09 `config.js`의 `HUB_URL`과 `KAKAO_REST_KEY`는 커밋한다.** 이유: 화면 파일만 있는 페이지라 이 값이 저장소에 있어야 동작하고, 두 값은 코이데 공개 저장소에도 있는 공개 값이다. 주소를 알아도 앱 관리자 카카오 계정이 아니면 아무것도 볼 수 없다. 비밀 열쇠·Client Secret·앱 관리자 목록은 여전히 넣지 않는다.
- **2026-11-09 화면 색을 코이데 먹색 테마(늘 밝게)로 바꾼다.** 위의 "늘 검은 색" 결정을 바꾼다. 이유: 사용자가 원한 것은 코이데 화면 설정의 먹색 테마였다(정정). 기기가 어두운 모드여도 늘 밝게 둔다(사용자가 정함).
- **2026-11-19 서버를 허브(Apps Script)에서 Supabase로 바꾼다.** 이유: 코이데·디다코가 이미 Supabase로 옮겼고, 운영자 기능(신청·교회·이용 통계)이 모두 Supabase 함수에 있다. 허브는 끈다(ⓕ).
- **2026-11-19 메뉴는 일곱 개로 한다.** 오늘, 교회 신청, 교회(스위치 켜고 끄기 포함), 이용 통계, 의견함, 공동체, 저장 공간. 이유: 사용자가 정했다(Q7 추천대로: 코이데 앱 안 `?appadmin` 신청 화면은 만들지 않고 이 사이트의 교회 신청 메뉴가 맡는다).
- **2026-11-19 이용 통계 그래프는 운영자 사이트에서 허용한다.** 사용자가 정했다(앱 화면 원칙과 별개). 범위(Q1·Q2 추천대로): 교회끼리 순위·비교와 개인 단위 표시는 계속 금지, 이용 통계는 교회 구분 없이 앱 전체 합계만, 5명 미만은 가리고 0으로 그리지 않는다. 교회 카드의 합계 숫자는 운영 사실이라 5명 미만도 그대로 보인다. 이용 통계 화면은 기록이 없어도 먼저 만들고 데모로 확인한다(Q5). 운영 기록(`admin_log`)은 둔다(Q4), 로그인은 이 기기에 유지하고 공용 컴퓨터는 로그아웃하도록 안내한다(Q3).
