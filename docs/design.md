# 설계서 (koinobia-admin)

설계의 기준은 이 파일 하나다. 전체 계획과 단계는 `plan.md`.

## 1. 무엇인가
코이데·디다코·(나중에) 텔리오의 이용 통계와 운영 도구를 한곳에 모은 운영자(앱 관리자) 전용 페이지. 앱 관리자만 들어온다. 서버는 pray-for의 Supabase다. 메뉴는 일곱 개다: 오늘, 교회 신청, 교회(스위치 포함), 이용 통계, 의견함, 공동체, 저장 공간. 기록 내용(이름·기도제목·기록 글)은 보이지 않는다(예외 셋은 아래 표).

## 2. 지킬 약속 5가지 (모든 PR 검토 때 이 표로 본다)

| 약속 | 어떻게 지키나 | 확인 방법 |
|---|---|---|
| 기록 내용이 안 보인다 | 이름·기도제목·기록 글을 부르는 서버 함수를 만들지 않는다. 예외는 운영자가 읽으라고 받은 글 셋뿐: 의견함 글, 교회 신청서(연락처·대표 목사님 이름), 공동체 신고 상세 | `js/api.js`가 부르는 함수 목록이 4장 표와 같은지, 셋 밖에 글을 싣는 함수가 없는지 |
| 이용 통계의 선 5가지를 지킨다 | 이름·내용을 모으지 않는다, 개인 단위로 안 보여 준다, 5명 미만은 가린다(0으로 그리지 않음), 13개월만 본다, 처리방침을 먼저 한다(`usage-stats.md`) | 데모 `?demo=small`·`?demo=empty`, 결과에 사람·교회 번호가 없는지 |
| 교회끼리·사람끼리 순위·비교가 없다 | 교회 목록은 만든 순서, "많은 순" 정렬 없음, 이용 통계는 교회 구분 없이 앱 전체 합계만 | 화면 검토 |
| 교재·편성·리더 지정이 없다 | 교재 칸·버튼, 부서·사랑방 편성, 리더 지정을 만들지 않는다. 교회 단위까지만 | 화면과 코드에 해당 낱말이 없는지 |
| 숫자와 그래프는 이 사이트에서만 | 앱 화면은 숫자로 재지 않는다(앱 원칙). 운영자 사이트의 숫자·그래프는 이용 통계 메뉴에만, 앱 전체 합계로만 | 이용 통계 밖에 그래프가 없는지 |

덧붙임: "받은 일 개수"(신청·의견·신고·저장 공간)와 교회 카드의 합계(가입 수, 부서 수 등)는 이용 행동이 아니라 운영 사실이므로 5명 미만이어도 가리지 않는다. 개인 이름은 싣지 않는다.

비밀값(`service_role`, `sb_secret`, Supabase 콘솔 비밀, 시트 주소, PIN)과 실제 이름은 저장소에 올리지 않는다. 사이트에는 `SUPABASE_URL`과 publishable 키만 둔다.

## 3. 화면 원칙
- 코이데 먹색 테마, 늘 밝은 화면. 코이데 먹색(ink) 테마의 밝은 값을 `css/admin.css` `:root`에 고정하고 `color-scheme: light`. 어두운 모드·기기 설정 분기 없음. 새 색을 만들지 않는다.
- 글꼴·크기는 코이데와 같다(제목 Gowun Batang, 본문 IBM Plex Sans KR, 휴대폰 16px, PC 15px). 터치 영역 44px 이상.
- 이모지·장식 없음. 서버가 준 글은 글자로만 넣는다.
- 화면 흐름: 로그인 전 → (앱 관리자 아님이면 안내 + 로그아웃) → 일곱 메뉴(오늘, 교회 신청, 교회, 이용 통계, 의견함, 공동체, 저장 공간) → 푸터(화면 버전·로그아웃). 위험한 동작(멈춤·만들기·거절·닫기·스위치 켜기)은 한 번 더 확인 단계를 둔다.
- 로그인 전: 가능한 방법마다 버튼(카카오·구글·애플, 목록은 Supabase 설정에서 읽고 실패하면 카카오), 공용 컴퓨터 안내. 로그인은 이 기기에 유지된다(`storageKey: koinobia-admin-sb`). 로그인에서 돌아온 `?code`는 주소에서 지운다.
- 앱 관리자 아님: 내 계정 번호(복사 버튼)·로그인 방법을 보여 주고 "코이데에서 쓰던 방법과 같은지 확인", "번호를 채팅·GitHub에 올리지 마세요", 로그아웃.
- 껍데기: 메뉴 줄(휴대폰에서 가로로 밀림, 각 44px 이상), 해시 주소(`#/today` 등)로 이동하고 새로고침해도 그 메뉴. 메뉴 옆 배지는 오늘 결과(신청 기다림·안 읽은 의견·새 신고). 푸터에 로그인 방법·화면 버전·로그아웃. 아직 없는 메뉴는 "준비 중".
- 오늘: 신청 기다림·안 읽은 의견·새 신고·활동 관리자 없는 교회·멈춘 교회(0이면 줄을 숨김, 모두 0이면 "오늘 할 일이 없어요"), 저장 공간(70% 넘으면 주황), 교회 수, 스위치 세 개의 상태(켜짐·관리자만·꺼짐), `usage_track`이 꺼져 있으면 한 줄 안내.
- 이용 통계: 위에 앱 고르기(전체·코이데·디다코·텔리오)와 기간(7·30·90·365일), 아래에 탭 여섯(한눈에·기능·흐름·다시 오는 사람·시간·기기·앱). 탭을 열 때만 그 탭의 함수를 부르고, 같은 요청은 60초 기억한다. 그래프는 `js/charts.js`가 직접 SVG로 그린다(꺾은선·세로/가로 막대·시간대 지도·깔때기·코호트 표·숫자 타일). 각 그래프는 `role="img"`와 요약 `aria-label`, "표로 보기" 단추를 가진다. 서버가 가린 값(`small`)은 0이 아니라 점선 빈 칸과 "5명 미만"으로 그린다. 색은 기존 변수만 쓰고 여러 줄은 실선·점선으로 나눈다. 흐름 탭의 미리 만든 흐름 4개는 usage-stats.md 4장 이름을 쓴다(교회 첫 접속은 건너뛰는 화면이 있어 단계 셋만).
- 보안 머리글(CSP)은 `index.html` 메타로 둔다(`script-src 'self'`, `connect-src`는 Supabase 한 곳). `connect-src`의 호스트는 `config.js`의 `SUPABASE_URL`과 같게 손으로 맞춘다(바뀌면 둘 다 고친다).
- 서비스워커·홈 화면 앱은 두지 않는다. 화면 버전은 `config.js`의 `VERSION`.

## 4. 서버를 부르는 방식
- 서버 부르기는 `js/api.js` 한 파일에만 둔다. 화면 코드는 `api.today()`처럼 뜻으로만 부르고 서버 함수 이름·요청 모양을 모른다.
- 로그인은 `supabase-js`(Supabase 로그인)가 한다. 관리자 판정은 서버(`admin_me`)만 믿는다. 화면에서 메뉴를 숨기는 것은 편의일 뿐이다.
- 모든 함수는 `authenticated`만 부를 수 있고, 첫 줄에서 앱 관리자인지 본다(`admin_me`만 예외). 인자 모양은 pray-for `supabase/`의 SQL 머리 주석을 본다.

| 메뉴 | 서버 함수(pray-for) |
|---|---|
| 로그인 | `admin_me`(036) |
| 오늘 | `admin_today`(036) |
| 교회 신청 | `church_apply_admin_list`, `church_apply_make`, `church_apply_reject`(035) |
| 교회·스위치 | `admin_church_list`, `admin_church_create`, `admin_church_rename`, `admin_church_state`, `admin_church_code`, `admin_church_invite`, `admin_setting_list`, `admin_setting_set`, `admin_log_list`(036) |
| 이용 통계 | `admin_usage_active`, `_signups`, `_retention`, `_features`, `_funnel`, `_heatmap`, `_devices`, `_cross_app`, `_dormant`(006), `admin_usage_stickiness`, `_frequency`, `_duration`, `_new_returning`(037) |
| 의견함 | `admin_feedback_list`, `admin_feedback_mark_read`(006) |
| 공동체 | `admin_community_health`, `admin_community_lookup`, `admin_community_close`(005·006), `admin_community_reports`(036) |
| 저장 공간 | `admin_db_size`(006) |

- 036·037이 서버에 아직 없으면 해당 메뉴는 "서버 SQL이 아직 없어요"를 보여 준다.
