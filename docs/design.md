# 설계서 (koinobia-admin)

설계의 기준은 이 파일 하나다. 전체 계획과 단계는 `plan.md`.

## 1. 무엇인가
코이데·디다코·(나중에) 텔리오를 한곳에서 관리하는 앱 관리자용 페이지. 앱 관리자만 들어온다. 교회 서버 상태와 숫자만 본다. 기록 내용은 어디에도 보이지 않는다.

## 2. 지킬 약속 5가지 (모든 PR 검토 때 이 표로 본다)

| 약속 | 어떻게 지키나 | 확인 방법 |
|---|---|---|
| 기록 내용이 어디에도 안 보인다 | `admin`이 주는 숫자·버전·오류 줄 수만 그린다. 이름·기도제목·기록을 부르는 요청은 만들지 않는다 | 요청 이름이 `login, admin, churchSave, enterPass, invite`(2단계 `leave`)뿐인지 |
| 기록 관련 숫자(쓴 사람 수, 기록 수, 작성률, 마지막으로 쓴 때)가 안 보인다 | 디다코 칸은 `{version, errors}`만 그린다. 서버가 더 보내도 그리지 않는다 | 화면에 해당 낱말이 없는지, 데모에 일부러 넣은 여분 값이 안 나오는지 |
| 교재 만들기·고치기·배포가 없다 | 교재 칸·버튼·요청이 없다 | 화면과 코드에 "교재" 낱말이 없는지 |
| 부서·사랑방 편성, 리더 지정이 없다 | 교회 단위(카드)까지만 | 위와 같음 |
| 순위·숫자 비교·댓글 같은 장치가 없다 | 카드는 시트 순서. 정렬·"많은 순"·그래프 없음 | 화면 검토 |

비밀값(`HUB_SECRET`, 카카오 Client Secret, 앱 관리자 목록, 시트 주소, PIN)과 실제 이름은 저장소에 올리지 않는다. 디다코 서버 상태는 반드시 기본 서버가 대신 묻는다(브라우저가 직접 부르지 않는다).

## 3. 화면 원칙
- **늘 검은(어두운) 화면.** 코이데 먹색(ink) 테마의 어두운 값을 `css/admin.css` `:root`에 고정하고 `color-scheme: dark`. 밝은 모드·기기 설정 분기 없음. 새 색을 만들지 않는다.
- 글꼴·크기는 코이데와 같다(제목 Gowun Batang, 본문 IBM Plex Sans KR, 휴대폰 16px, PC 15px). 터치 영역 44px 이상.
- 이모지·장식 없음. 서버가 준 글은 글자로만 넣는다.
- 화면 흐름: 로그인 전 → (앱 관리자 아님이면 서버 문장 + 로그아웃) → 교회 카드 목록(1-2부터) → 푸터(기본 서버 버전·내 카카오ID·화면 버전·로그아웃).
- 서비스워커·홈 화면 앱은 두지 않는다. 화면 버전은 `config.js`의 `VERSION`.

## 4. 서버를 부르는 방식
- 서버 부르기는 `js/api.js` 한 파일에만 둔다. 화면 코드는 `api.admin()`, `api.login(code)`처럼 뜻으로만 부르고 기본 서버 주소·요청 모양을 모른다.
- 나중에 Supabase로 바꿀 때는 `api.js` 안쪽만 갈아 끼운다. 화면 코드는 그대로다.
- 지금은 기본 서버 요청 `login`, `admin`을 쓴다. 앱 관리자 판정은 서버(`APP_ADMINS`)가 한다.

## 5. 결정 기록
- **2026-11-09 관리 페이지를 새 저장소에 따로 둔다.** 이유: 코이데 화면 파일이 커서 관리 화면을 고칠 때마다 코이데 전체·캐시 번호·배포를 건드려야 하고, 다른 주소에 두면 앱 관리자 로그인이 일반 앱 화면과 섞이지 않는다.
- **2026-11-09 서버는 지금 기본 서버를 그대로 쓴다(새 서버 없음).** 이유: 비밀 열쇠가 있는 곳을 늘리지 않고, 사용자가 할 서버 일을 줄인다.
- **2026-11-09 화면은 늘 검은 색으로 고정한다.** 이유: 사용자가 정했다. 코이데 먹색 어두운 값을 쓰고 밝은 모드는 두지 않는다.
- **2026-11-09 저장소는 공개, 주소는 `admin.koinobia.com`(GitHub Pages).** 이유: 비밀값이 없고 koide도 공개다. 다른 하위 주소라야 대문(`koinobia.com`)과 브라우저 저장소를 나눠 쓰지 않는다.
- **2026-11-09 서버 부르기는 `js/api.js` 한 곳에만 둔다(Supabase 대비).** 이유: 나중에 Supabase로 바꿀 때 화면 코드를 고치지 않고 `api.js` 안쪽만 바꾸려고.
- **2026-11-09 관리자가 명단에서 사람을 뺄 때 디다코 기록은 지우지 않는다.** 지우기는 본인이 나갈 때만 한다. 이유: 실수로 지우면 되돌릴 수 없다.
- **2026-11-09 디다코 교회 관리자를 누가 세울지는 3단계에서 정한다.** 당분간 앱 운영자가 겸한다.
- **2026-11-09 "이 교회로 들어가기"는 일회용 통행증(enterPass/enterOpen) 방식으로 한다.** 이번 뼈대 PR에서는 만들지 않는다(1-5).
